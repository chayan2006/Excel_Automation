# Excel Automation System

This project automates monthly Excel file ingestion, validation, deduplication, and master workbook updates.

## Project structure

- `input/` – raw monthly Excel files placed by users or system automation.
- `processed/` – successfully processed files moved after the run.
- `errors/` – files moved after validation failures or unreadable input.
- `output/` – generated intermediate or output files if expanded later.
- `backups/` – automatic backups of `Master.xlsx` before updates.
- `reports/` – CSV error reports and JSON processing summaries.
- `logs/` – run logs generated by the application.
- `config/config.json` – centralized configuration for sheet names, required columns, naming rules, and update logic.
- `src/` – application code.

## How it works

1. The scheduler or user drops Excel files into `input/`.
2. The application scans the folder for `.xlsx` and `.xlsm` files.
3. Each file is validated against the configured sheet, naming pattern, and required columns.
4. Empty rows, missing values, invalid dates, and duplicate identifiers are detected.
5. Valid files are compared against the master workbook.
6. New rows are appended, existing rows are updated according to the configured business rules.
7. A backup of the master workbook is created before changes are made.
8. Successfully processed files are moved to `processed/` and failed files to `errors/`.
9. Logs and reports are written to the `logs/` and `reports/` folders.

## Configuration

Update `config/config.json` whenever the company changes:

- workbook sheet name
- required columns
- filename pattern
- key columns used for duplicates and updates
- update rules for existing records

Example:

```json
{
  "sheet_name": "Monthly Data",
  "required_columns": ["Employee ID", "Name", "Department", "Salary", "Date"],
  "identifier_columns": ["Employee ID"],
  "filename_pattern": "^(?:[A-Za-z]+_\\d{4}|\\d{4}-\\d{2})\\.(?:xlsx|xlsm)$",
  "business_rules": {
    "update_columns": ["Department", "Salary", "Date"]
  }
}
```

If your files use a different naming convention, change the regex in `filename_pattern`.

## Running the automation

### Option 1: Manual run

```bash
python src/main.py
```

### Option 2: Windows Task Scheduler

Use the included `run_automation.bat` file in Windows Task Scheduler.

```bat
@echo off
cd /d "%~dp0"
python src\main.py
```

### Option 3: Local web dashboard

Install the requirements and start the upload dashboard from the project root:

```bash
pip install -r requirements.txt
python app.py
```

Open `http://127.0.0.1:5050` in a browser.

### Option 4: Production Docker / Docker Compose

Deploy the application in a lightweight container with persistent volumes for Excel files, reports, and backups:

```bash
docker compose up -d --build
```

Access the dashboard at `http://localhost:5050`. See [DEPLOYMENT.md](DEPLOYMENT.md) for complete deployment instructions, volume details, and production tuning.


Master uploads must be valid `.xlsx` workbooks. `.xlsm` files are accepted as monthly inputs only; this avoids silently stripping macros from a master saved as `Master.xlsx`. Invalid master uploads leave the current workbook intact. Uploading a filename that is already queued keeps the original queued file and displays a message.

Blank rows are skipped when `business_rules.skip_blank_rows` is enabled. Updates retain the original Excel row positions, including gaps, and duplicate records are checked using the complete set of `identifier_columns`. Duplicate identifiers in the master block an update instead of choosing an arbitrary row. Master changes are saved to a temporary workbook before replacing the live file.

The dashboard also supports telecom invoice PDFs. Upload one or more native-text PDF bills in the invoice panel and select **Extract to Excel**. Vendor detection currently supports Airtel, Jio, Vodafone Idea, and an Unknown fallback. Reports are saved as `reports/telecom_invoices_<timestamp>.xlsx`, with the source PDF, detected vendor, invoice number, invoice date, account number, total amount, GSTIN, and extraction status. Scanned image-only PDFs need OCR before their fields can be extracted.

### Preview and apply

- Preview runs the same validation and update code on temporary copies. It does not alter the master, move queued files, or create live reports and backups.
- Totals show added, updated and unchanged rows plus invalid files. Before/after values are shown for up to 200 changed rows per file; totals cover all rows.
- Files are previewed in the same sorted order as the real run. Later files see the changes proposed by earlier ones.
- A preview expires after one hour. Changing any queued workbook, the master, or the processing configuration invalidates it and requires another preview.
- Applying processes valid files and moves invalid ones to `errors/`, with an error report. If all files are invalid, the button explicitly offers to save the report and archive those files.

### Errors, history and recovery

The dashboard shows the ten most recent readable run summaries, with JSON summary and CSV error downloads. **Errors & corrections** shows the file, worksheet, row, column and a suggested fix. It displays up to 200 errors; download the CSV for the full list. Correct the original workbook and upload it again.

**Master backups** lists saved masters with download links. Select **Review restore** to inspect the selected backup's worksheet names and row counts, then **Confirm restore**. The current master is backed up first; the selected backup replaces it only after validation. Queued files and previous reports are unaffected. If the master or selected backup changes before confirmation, the restore is blocked until reviewed again.

Preview and restore forms use CSRF protection and signed confirmations. Set `EXCEL_AUTOMATION_SECRET` to a long private value if sessions should survive a server restart; otherwise the app generates a new secret at startup. Use one local server process and avoid running the CLI or editing workbooks in Excel at the same time as a dashboard operation. Dashboard workbook operations are serialized within that process; there is no cross-process or external-editor lock.

## Invoice review workspace

`http://127.0.0.1:5050/review` (or **Review workspace** on the dashboard) is a document-capture screen for invoices: every extracted value is checked against the PDF by a person before it is exported. The workflow follows hosted capture tools such as Rossum.

### Workflow

1. Upload PDFs on the **Documents** page (button or drag and drop) into a queue. The data is extracted in the background.
2. Open a document from the **To review** tab, or select **Start reviewing**. Values the extractor is unsure about are marked **Check**.
3. Correct values by typing, or select a field and draw a box around the value on the page to capture it. **Enter** accepts a value and moves to the next one to check.
4. **Confirm** the document (Ctrl+Enter). Errors such as an empty required field or an invalid GSTIN block confirmation. Warnings such as totals that do not add up do not.
5. Export confirmed documents to Excel from the review screen or in bulk from the **Confirmed** tab. Files are saved as `reports/review_export_<timestamp>.xlsx`, with one row per document plus a sheet per table (tax breakdown, line items).

A document is always in one of these statuses: Importing, Import failed, To review, Postponed, Confirmed, Exported, Rejected, Deleted. Postponed documents can still be edited. Confirmed, exported and rejected documents are read-only until someone selects **Return to review**, and deleted documents can be restored.

### Review screen

- The fields sidebar groups values into sections, with tables for the tax breakdown and line items (add and delete rows).
- The document viewer shows bounding boxes for every value; selecting a field highlights it on the page and clicking a box selects its field. It has zoom (+, −, 0 or Ctrl+wheel), page thumbnails and a page jump, and only loads the pages near the visible area, so 400-page bills open quickly.
- The **Confidence** switch shows extraction scores and **Hidden fields** shows fields the schema hides.
- Other features: an activity log of every change, a document info panel, labels, moving documents between queues, re-extract, reject or postpone with a note, and download of the original PDF.
- Shortcuts: Enter (accept and go to next), Tab, Ctrl+Enter (confirm), N (next value to check), [ and ] (previous and next document), ? (shortcut list).

If a field fails to save, its draft remains visible and document actions are blocked. Press Enter in the affected field to retry. A successful save of another field does not clear that failure, and leaving the page warns about pending or unsaved edits.

The person named under **Reviewing as** on the Documents page is recorded in the activity log and on confirmations. It is a name, not a login: there are no accounts, permissions or document locks, so agree who works on which queue.

### Extraction and confidence

`src/document_extractor.py` finds each value with a regex on the page text and keeps its position. Each value gets a confidence score based on how it was found:

| Score | Meaning |
| --- | --- |
| 0.99 | Vendor or generic rule, confirmed by an arithmetic check (for example subtotal + tax = total) |
| 0.95 | Vendor template rule (Airtel; checked against real enterprise voice and data bills) |
| 0.85 | Vendor rule that has not been checked against real bills yet (Jio, Vodafone Idea) |
| 0.70 | Generic pattern used when there is no vendor template |
| 0.30 | Text was found but is not a valid value for the field |

Values below `score_threshold` (default 0.9) are marked **Check**. To support a new vendor, add a rule set to `VENDOR_TEMPLATES` in `src/document_extractor.py` and a detection rule to `classify_vendor` in `src/invoice_extractor.py`.

### Configuration

- `config/review_schema.json` lists the sections and fields (type `string`, `number`, `date`, `enum` or `table`; `required`, `hidden`, `multiline`, `"format": "gstin"`) and the arithmetic `checks` that produce warnings.
- `config/review_config.json` sets the workspaces and queues, the default queue, `score_threshold`, the dashboard list columns, page image resolution and page size. Its `automation_level` is `never` (every document is reviewed), `confident` (documents with no warnings and nothing to check are confirmed automatically) or `always` (anything without errors is confirmed).

Documents, the SQLite database and cached page images are stored in `output/review/`.

### Limitations

- Scanned (image-only) PDFs open in the viewer, but nothing can be extracted or captured from them without OCR.
- Documents arrive by upload only; there is no email inbox import.
- Pages cannot be split, rotated or deleted.

## Regression checks

Run from the project root:

```bash
python3 -m unittest discover -s tests -v
node --test tests/review_saves.test.cjs
```

The Python tests use temporary workbooks and upload folders. The JavaScript tests use a controlled network stub to check save ordering, failure recovery, and confirmation guards. Neither suite modifies live documents.

## Notes

- The application is intentionally configurable rather than hardcoded to a single file layout.
- It preserves existing workbook structure by editing the live `Master.xlsx` workbook in-place instead of rewriting the full file.
- The code is designed for a lightweight Windows environment using Python, pandas, and openpyxl.
